## 为什么做 Sunbridge

Sunshine 是很好用的串流主机，但想连上它，每台设备都得先装客户端。在公司电脑、借来的平板、不方便装软件的设备上，这一步往往就卡住了。

Sunbridge 跑在你自己的电脑上（通常就是装 Sunshine 的那台），把串流转成一个网页。只要有浏览器，登录后就能看到桌面、玩游戏、用键鼠和手柄。

- **零安装**：浏览器打开网址即可，手机、平板同样能用
- **为外网优化**：自动选 AV1 / HEVC，按网络状况调整码率，断线自动重连
- **远程桌面和游戏两用**：普通指针 + 触屏手势，或锁定鼠标 + 手柄
- **私有部署**：数据只在你自己的电脑上，带登录、HTTPS 和访问限制

## 特点

### 画面与带宽

- **自动选择最省带宽的编码**：按实际串流的分辨率和帧率检测浏览器能否硬件解码 AV1 / HEVC，能就用（同等画质下比 H.264 省 30–50% 码率），不能就让主机直接编码 H.264；串流中发现硬解不可用或软解跟不上，也会自动切换。
- **只转发、不转码**：画面就是主机编码的原始码流，浏览器直接用 WebCodecs 解码，没有二次编码的画质损失和延迟。接收、解码和绘制都在独立线程（Worker）里，页面卡顿不会拖慢画面；解码器按实际码流和分辨率优先选硬件。
- **去掉冗余**：Sunbridge 在本机把视频组装成完整帧再发给浏览器，不再传送纠错冗余和包头，外网带宽实测省约 25–30%，省下的预算交给编码器提升画质。
- **自适应分辨率**：按浏览器窗口的实际像素请求分辨率，文字清晰、不糊；改变窗口大小、旋转、全屏时自动跟随（最多每 4 秒切换一次）；串流顶栏可一键固定当前分辨率。

### 网络与稳定

- **WebRTC（UDP）传输**：画面和声音走 UDP，路上丢一个包只影响那一帧，不会像 TCP 那样卡住整条连接，经过 VPS / 跨运营商的线路也能跑满带宽；UDP 不通时自动改用 WebSocket。需要放通一个 UDP 端口，见[常见问题](#常见问题)。
- **两段自适应码率**：主机 → Bridge（丢包、FEC 无法恢复的帧）和 Bridge → 浏览器（排队延迟、积压、实际带宽）分别探测，取较低者作为目标，统计面板分开显示两段；设定的码率是上限，实际码率超出会被自动压回去。
- **延迟有上限**：网络拥塞时按整帧丢弃并跳到下一个关键帧，画面只会短暂停顿，不会花屏，也不会越积越慢。
- **断线自动重连**：网络切换、电脑休眠唤醒、服务重启后自动恢复；刷新页面可以一键回到正在进行的串流。
- **清晰的状态反馈**：主机结束串流、应用退出、画面中断，页面都会明确告诉你发生了什么。

### 操作

- **剪贴板同步**：本机和主机之间同步复制的文本和图片（PNG），大图片走主机的 HTTPS 通道。需要主机是 [Foundation Sunshine](https://github.com/AlkaidLab/foundation-sunshine)，在它的设置里打开剪贴板同步并保持 Sunshine 桌面程序运行；浏览器第一次会询问是否允许读取剪贴板，不允许时可用串流工具栏的按钮手动发送。在串流画面上按 Ctrl+V 会先把本机剪贴板（包括在文件管理器里复制的图片文件）送到主机再粘贴；也可以把图片拖到画面上。协议只支持文本和图片，普通文件无法通过剪贴板传输。
- **远程桌面模式**：鼠标按绝对位置点击；触屏单指点按 / 拖动、长按或双指点按右键、双指滑动滚动；屏幕键盘支持中文。
- **游戏模式**：锁定鼠标、相对移动，支持手柄和震动。
- **全屏捕获系统按键**：全屏后 Win、Alt+Tab、Esc 等可以直接发给主机（浏览器允许时）。
- **交互测试与诊断报告**：“网络”页可以测浏览器到 Sunbridge 的往返和上下行速度，用和串流相同的方式模拟全屏、键盘锁定和鼠标锁定，逐个检查按键能否到达网页，并一键复制或下载诊断报告用于反馈。
- **声音**：Opus 立体声，播放端带抖动缓冲和时钟漂移校正，网络波动时不爆音。

### 管理与安全

- **网页里设置一切**：首次启动后在浏览器里创建账户；访问方式、证书、两步验证都在网页里改，`start.bat` / `start.sh` 只负责启动和救援。用 git 安装时，可以在“偏好设置”页检查更新并一键更新、重启。
- **多入口**：可以同时开多个端口，各自选择 HTTPS、是否只接受反向代理；比如一个给本机 nginx，一个通过路由器端口转发直连。按访问的域名自动选用证书，并可限制允许访问的域名。
- **日志**：登录、被拒绝的连接（地址不允许、代理不可信、跨站请求）、设置修改和串流都有记录，网页“日志”页可筛选查看。
- **主机管理**：修改地址、端口、网络唤醒；单独设置每台主机的分辨率、帧率、码率和控制模式。
- **安全**：所有页面和接口都需要登录；可选两步验证（验证器 App 动态码，可分别用于登录、开始串流、恢复会话）；登录失败限速；跨站请求防护；配对私钥和账号数据永远不会通过网页暴露。

## 工作原理

```
                 同一台电脑（或同一局域网）                    外网 / 局域网
┌───────────┐   UDP（RTP / FEC）   ┌─────────────┐  WebRTC / WebSocket   ┌──────────────┐
│ Sunshine  │ ───────────────────▶ │  Sunbridge  │ ────────────────────▶ │    浏览器    │
│ （编码）  │ ◀─────────────────── │ （转发服务）│ ◀──────────────────── │ （WebCodecs）│
└───────────┘   控制流（加密）     └─────────────┘   键鼠 / 手柄 / 触屏   └──────────────┘
```

Sunbridge 负责与 Sunshine 配对、协商串流、接收媒体，并把画面组装成完整帧发给浏览器：能连上 UDP 时走 WebRTC，否则走 WebSocket；控制消息和输入始终走 WebSocket。浏览器负责解码、播放和采集输入。它与 Sunshine 之间使用标准的 GameStream 协议，不需要修改主机端。

## 快速开始

需要 [Node.js](https://nodejs.org/) 18 或更高版本（推荐 20+），以及一台运行 Sunshine 的主机。

```bash
git clone https://github.com/Ainierheokami/sunbridge.git
cd sunbridge
./start.sh        # Windows：双击 start.bat
```

1. 在菜单里选 **启动**。默认监听所有网卡的 8091 端口（HTTPS，自签名证书），窗口里会显示访问地址和一个 **设置码**。
2. 用任意设备的浏览器打开 `https://<这台电脑的 IP>:8091/`，确认继续访问（自签名证书会有提示），输入设置码、用户名和密码 **创建账户**。
3. 点“添加主机”，填 Sunshine 的地址，输入 Sunshine 网页上显示的 PIN 完成配对。
4. 需要用域名、反向代理或路由器端口转发访问时，到 **访问设置** 里添加入口、上传证书、填写允许的域名；保存后 60 秒内要在新地址上点“保留”，否则自动恢复，不怕把自己锁在外面。

> 浏览器只在 HTTPS 或本机访问时开放视频解码、手柄和鼠标锁定，所以从其他设备访问时需要 HTTPS。

脚本只保留几个命令：`start`、`status`（访问地址、设置码、最近的警告）、`reset-network`（网页打不开时恢复默认网络设置）、`passwd`、`logout-all`、`2fa-off`。`./start.sh help` 查看说明。

## 使用说明

| 操作 | 方式 |
| --- | --- |
| 切换远程桌面 / 游戏模式 | 串流顶栏的模式按钮 |
| 全屏（可捕获系统按键） | 串流顶栏的全屏按钮 |
| 释放鼠标 | Ctrl+Alt+Shift+Z |
| 结束串流 | Ctrl+Alt+Shift+Q 或顶栏“结束会话” |
| 串流统计（帧率、流量、延迟分解） | 右上角状态条，或 Ctrl+Alt+Shift+S |
| 屏幕键盘（触屏设备） | 远程桌面模式下顶栏的键盘按钮 |

设置页可以调整默认分辨率（默认“自适应”）、帧率、视频编码（默认“自动”）、码率控制和控制模式；每台主机还可以在主机列表右侧的 ⋯ 里单独设置。

**设置 → 外观与文字** 里可以选择浅色、深色或跟随系统主题，并把文字调大（较大 / 特大），只影响当前浏览器。

### 两步验证

在 **设置 → 两步验证** 里启用：确认密码后，用手机上的验证器 App（Google Authenticator、Microsoft Authenticator、腾讯身份验证器、1Password 等）扫码，输入 6 位验证码即可。启用时会给出 10 个一次性恢复码，请妥善保存；同时其他已登录的设备会被退出。

可以分别选择在哪些场景要求验证码：

| 场景 | 说明 |
| --- | --- |
| 登录时（默认开启） | 输入密码后还要输入验证码 |
| 开始串流时 | 启动新串流前验证 |
| 恢复会话时 | 接入不是当前浏览器开始的串流（换设备继续、接管）前验证；自己断线重连、刷新页面不受影响 |

验证通过后 5 分钟内不会重复询问。手机和恢复码都丢了：在运行 Sunbridge 的电脑上执行 `./start.sh 2fa-off`（Windows：`start.bat 2fa-off`）关闭两步验证。只能通过 HTTPS 或在本机设置两步验证，避免密钥以明文经过网络。

## 目录

```
sunbridge/
├─ start.bat / start.sh   启动和管理
├─ app/                   程序文件（升级时整个替换；首次启动会自动安装依赖到 app/node_modules）
├─ data/                  你的数据（首次运行后生成，已在 .gitignore 中排除）
└─ docs/                  文档图片
```

`data/` 里有配对私钥、账号和证书：**不要分享、不要提交到仓库**；升级时保留它，只替换 `app/`。

## 环境变量（可选）

一般在网页里设置即可，配置保存在 `data/config.json`。设置了下面的端口 / 监听变量时，以环境变量为准（只有一个入口），网页上的入口设置变为只读。

| 变量 | 作用 |
| --- | --- |
| `SUNBRIDGE_PORT` | 端口，默认 8091 |
| `SUNBRIDGE_BIND` | 监听地址，如 `127.0.0.1`、`0.0.0.0` |
| `SUNBRIDGE_TLS` | `off` 关闭 HTTPS，其他值开启 |
| `SUNBRIDGE_TLS_CERT` / `SUNBRIDGE_TLS_KEY` | 证书和私钥文件 |
| `SUNBRIDGE_TRUST_PROXY` | `1`：由反向代理提供 HTTPS |
| `SUNBRIDGE_TRUSTED_PROXIES` | 允许连接的反向代理地址，如 `127.0.0.1,172.16.0.0/12` |
| `SUNBRIDGE_ALLOWED_ORIGINS` | 额外允许的页面来源，如 `https://example.com` |
| `SUNBRIDGE_DATA_DIR` | 数据目录，默认 `data/` |

## 常见问题

**连不上或画面异常，从哪里查起？**
打开“网络”页点“运行诊断”：会逐段检查主机端口、Sunshine 状态和配对、RTSP、Bridge 的入口和 WebRTC，并从浏览器实际建立一次 WebRTC 连接测试 UDP 是否连通；串流中运行还会显示视频 / 音频 / 控制通道的 UDP 收包和丢包。

**画面迟迟不出来？**
打开串流统计看“编码”和“视频解码”。设备不支持硬件解码 AV1 / HEVC 时会自动用 H.264；也可以在设置里手动指定 H.264。

**外网卡顿、经过 VPS 跑不满带宽？**
先看统计面板“画面”里的“媒体通道”：显示 WebSocket（TCP）时，丢包会卡住整条连接，经过 VPS 的线路尤其明显，请按下一条打开 WebRTC。已经是 WebRTC 还卡，再把码率上限设为略低于上行带宽；“排队延迟”持续很高说明带宽不够。

**怎么让 WebRTC 生效？**
需要让浏览器能连到 Bridge 的一个 UDP 端口，默认与网页端口同号（如网页是 8091/TCP，UDP 也用 8091）：
- 直连：路由器把这个 UDP 端口转发到运行 Sunbridge 的电脑，防火墙放行。
- 经过 VPS（EasyTier / frp 等）：在 VPS 上再加一条**同端口的 UDP 转发**到这台电脑，VPS 安全组放行 UDP。例如 EasyTier：`--port-forward udp://0.0.0.0:8091/<电脑的虚拟 IP>:8091`。
- 地址默认用浏览器打开网页时的域名或 IP；经反向代理或 UDP 端口号不同时，在“访问设置 → WebRTC（UDP）”里填写公网地址和端口。

连不上时会在约 8 秒后自动改用 WebSocket，统计面板会显示原因。依赖 `node-datachannel` 在首次启动时自动安装；装不上（离线、访问 npm 受限）时 WebRTC 不可用，其余功能不受影响。可以运行 `./start.sh deps`（Windows：`start.bat deps`，或菜单里的“安装 / 修复依赖”）重新安装，它会说明失败原因，国内网络建议先 `npm config set registry https://registry.npmmirror.com`。

**地址栏显示证书有效，却有红色感叹号？**
通常是以前在这个域名上点过“继续前往（不安全）”。点地址栏左侧图标，选择“重新启用警告”，或重启浏览器。

**支持哪些浏览器？**
推荐最新版 Chrome / Edge（桌面和 Android）。其他支持 WebCodecs 的浏览器（较新的 Safari、Firefox）理论上可用，但还没有充分测试。HEVC 依赖系统的硬件解码支持。
